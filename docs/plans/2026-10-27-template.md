# Plan 1: template v2.1.1 and v2.2.0

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reshape `prosdevlab/ts-monorepo-starter` so the CLI can generate any subset of its examples by removing files and marked blocks only.

**Architecture:** Two releases. v2.1.1 is a patch: the pnpm guard and corrected docs, released right after Task 1. The Node 26 LTS pin (Task 2) ships in v2.2.0. v2.2.0 renames the examples by role, moves each example's tools into its own package, and marks every example-specific block in Markdown and YAML.

**Tech Stack:** pnpm 12.15.0, Turborepo, TypeScript 7 (plain `tsc`), Rollup, Vitest 5, Playwright, size-limit, knip, Biome, GitHub Actions.

**Spec:** the Design tab of this doc. Repo: `~/workspace/prosdev/ts-monorepo` (remote `prosdevlab/ts-monorepo-starter`).

## Global Constraints

- Pin exact versions, each at least 3 days old; never add `minimumReleaseAgeExclude`.
- One PR per task, merged by rebase; Conventional Commits; no `Co-Authored-By` lines; code comments 1–2 lines.
- Each release's notes end with "Changes for existing projects".
- Before a task is done: AGENTS.md "Before Calling Work Done" sequence, plus actionlint and zizmor when a workflow changes.
- The template still works through "Use this template": markers are comments that render as nothing.
- Marker syntax is fixed: Markdown `<!-- example:NAME -->` … `<!-- /example:NAME -->`, YAML `# example:NAME` … `# /example:NAME`; NAME is `lib`, `cli`, `web` or `template-only`. The scope stays `@monorepo`.

## Review Focus

1. A marker that is unbalanced, nested or misspelled. The CLI would cut the wrong text; Task 6's check must fail on each (tests in Task 6).
2. An example named outside its markers in docs or config. A generated repo would describe a removed package; Task 6's check simulates each removal and greps for the example's names.
3. Playwright moving into `packages/web`. The CI browser-cache key and `pnpm test:browser` must still find it (Task 5 verification).
4. knip after the moves. Each package's tools must stay detected with no `knip.json` special case (Task 5).
5. Projects created from v2.1.x porting v2.2.0. The release notes map every old name and path to the new one (Task 7).

## Task 6 (v2.2.0): markers and the marker check

Every line that belongs to one example sits between that example's markers, so removing the example is deleting its folders and its marked blocks.

**Marker forms:** Markdown `<!-- example:NAME -->` / `<!-- /example:NAME -->`; YAML `# example:NAME` / `# /example:NAME`; TypeScript, JavaScript and JSONC (`tsconfig.json`, `vitest.config.ts`, `knip.json` if it survives Task 5) `// example:NAME` / `// /example:NAME`. Each marker is alone on its line. NAME is `lib`, `cli`, `web` or `template-only` (lines only the template repo needs). With `//` markers in config there are no JSON keys left for the CLI to edit; if a file can't hold comments, the check reports it and the file moves into its example's folder instead.

**Files:**

- Create: `scripts/check-examples.mjs` (Node, no dependencies), `scripts/check-examples.test.ts`
- Modify: `vitest.config.ts` (`include` adds `scripts/**/*.test.ts`), `.github/workflows/ci.yml` (a step `node scripts/check-examples.mjs` after Lint, inside `# template-only` markers), every file with example-specific lines (README, AGENTS.md, ci.yml, `tsconfig.json`, `vitest.config.ts`, CONTRIBUTING, the issue form)

**Interfaces:**

- Produces: `checkExamples(files: Map<string, string>): Problem[]` where `Problem = { file: string; line: number; message: string }`, plus the CLI entry that reads every tracked text file (`git ls-files`), prints problems as `file:line message` and exits 1 if any. The example identifiers it greps for: `lib` → `packages/shared`, `packages/lib`, `@monorepo/shared`, `@monorepo/lib`; `cli` → `packages/cli`, `@monorepo/cli`; `web` → `packages/web`, `@monorepo/web`, `playwright`, `size-limit`, `axe-core`. The CLI's Task 4 reuses these marker forms and identifiers.

* [ ] **Step 1: Write the failing tests** in `scripts/check-examples.test.ts`, each on an in-memory `Map`:
  - `accepts balanced markers` → `[]`
  - `reports an unclosed marker` → message `example:web opened here is never closed`
  - `reports a nested marker` → message `example:cli opens inside example:web`
  - `reports an unknown name` → message `unknown example "webb"`
  - `reports an example named outside its markers`: README mentions `packages/web` unmarked → message `packages/web appears outside example:web markers`
  - `ignores identifiers inside the example's own folder` (`packages/web/README.md` may say `playwright`)
* [ ] **Step 2: Run** `pnpm test`. Expected: the 6 new tests fail (module not found).
* [ ] **Step 3: Implement** `checkExamples` and the entry.
* [ ] **Step 4: Run the check on the repo.** Expected: many "outside markers" problems. Add markers until it prints nothing.
* [ ] **Step 5: Prove removal works by hand.** On a scratch copy, for each of `lib`, `cli`, `web`: delete its folders and marked blocks (`perl -0pi` on the marker pairs), `pnpm install`, then the full CI sequence. Expected: all pass, knip included.

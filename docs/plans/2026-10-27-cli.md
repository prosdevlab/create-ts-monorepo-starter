
# Plan 2: create-ts-monorepo-starter CLI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `create-ts-monorepo-starter`, so `pnpm create ts-monorepo-starter` generates a working repo from any subset of the template's examples.

**Architecture:** A repository made from the template, holding one package. Its build fetches a pinned template release and ships those files next to one bundled ESM file with zero runtime dependencies. At run time it copies, renames, removes marked blocks, installs and commits in a temporary sibling folder, then renames it into place.

**Tech Stack:** TypeScript 7, `@clack/prompts` 1.x (bundled), `node:util` `parseArgs` and `styleText`, `node:child_process`, Rollup, Vitest 5, the template's CI and release workflows.

**Spec:** the Design tab of this doc; screens in [CLI screens]. Requires template v2.3.0 (Plan 1, then Dependabot in place of Renovate).


## Global Constraints

- The published package is `create-ts-monorepo-starter` (unscoped), bin `create-ts-monorepo-starter`, `engines.node` `>=22.13`, no `dependencies`.
- No telemetry. No network at run time except `pnpm install` and the `npm exec` fallback.
- Never delete a user's files: a non-empty target moves to `<folder>.backup-YYYYMMDD-HHMMSS`. Work happens in `.<folder>.tmp-<8 hex>` next to the target.
- Prompt and message wording comes from the CLI screens canvas; where a screen and this plan differ, the plan wins.
- Marker forms, example names and identifiers are those of Plan 1 Task 6.
- Pin exact versions at least 3 days old; one PR per task, rebase-merged; Conventional Commits; no `Co-Authored-By`; comments 1–2 lines.
- Creating the GitHub repository and the first npm publish are outward actions: stop and ask the user first. The repository is prosdevlab/create-ts-monorepo-starter on GitHub, checked out at ~/workspace/prosdev/create-ts-monorepo-starter. Dependency updates come from the template's Dependabot config; there is no Renovate.

## Review Focus

1. The folder is `.`, an absolute path, or has spaces or capitals. The project lands where asked, and the package name is a valid npm name (Task 3, Task 5 tests).
2. The target sits inside an existing git repository (a monorepo subfolder). Skip `git init` and the commit, and say so (Task 7 test).
3. stdin isn't a terminal and no folder was given. Exit 2 with `Pass a folder name, for example: create-ts-monorepo-starter my-tools` (Task 8 test).
4. Windows. Paths with backslashes in replacements, and a rename refused with `EPERM` or `EBUSY` that then succeeds on retry (Task 7 test with an injected error; Task 9 on `windows-latest`).
5. Ctrl-C during a prompt and during the install. Neither leaves a folder or a temporary folder behind (Task 9 tests).

## Task 7: git, backup and the move

**Files:** Create `src/workspace.ts`, `src/git.ts`; Test `test/workspace.test.ts`, `test/git.test.ts` (real temporary folders and real git).

**Interfaces:**

- Produces: `tempPath(target: string, random?: () => string): string` = `<parent>/.<name>.tmp-<8 hex>`; `backupPath(target: string, now: Date): string` = `<target>.backup-YYYYMMDD-HHMMSS` (local time)
- Produces: `targetState(target: string): Promise<'missing' | 'empty' | 'not-empty'>`; `backUp(target: string, now: Date): Promise<string>` (renames the folder, returns the backup path)
- Produces: `moveIntoPlace(temp: string, target: string, deps?: { rename?: typeof fs.rename; sleep?: (ms: number) => Promise<void> }): Promise<void>`. A missing target gets one `rename` of the whole folder. An empty target (including `.`) gets each top-level entry renamed into it, because the current directory can't be replaced. Each rename retries on `EPERM`, `EBUSY` or `EACCES` after 100, 200, 400, 800 and 1600 ms, then rethrows.
- Produces: `onInterrupt(temp: string): () => void`. It registers SIGINT and SIGTERM handlers that remove `temp` and exit 130, and returns the unregister function.
- Produces: `insideGitRepo(dir: string): Promise<boolean>`; `gitIdentity(): Promise<{ name?: string; email?: string }>`; `initAndCommit(dir: string, message: string): Promise<'committed' | 'no-identity' | 'no-git'>`. That runs `git init -q -b main`, `git add -A`, `git commit -q --no-verify -m <message>`. Without both `user.name` and `user.email` it initializes and stages but doesn't commit; it never invents an identity.

## Task 8: run, prompts, output and help

**Files:** Create `src/run.ts`, `src/ui.ts`; Modify `src/cli.ts`; Test `test/run.test.ts`, `test/ui.test.ts`, `test/cli.test.ts` (spawns the built `dist/cli.js`).

**Interfaces:**

- Consumes: everything from Tasks 2–7
- Produces: `interface RunPlan { target: string; folderName: string; scope: string; keep: Example[]; git: boolean; install: boolean; now: Date; holder: string }` and `planFromOptions(o: Options, cwd: string, now: Date, holder: string | undefined): RunPlan`. Defaults: `folder` none (asked, or an error without a terminal); `scope` `defaultScope`; `keep` all; `holder` `[YOUR NAME]`.
- Produces: `run(plan: RunPlan, ui: Ui, deps?: RunDeps): Promise<RunResult>`, in this order:

  2. `generate`
  3. `git init`, unless `!plan.git` or `insideGitRepo(parent)`
  4. install (`installCommand` with `lockfileOnly = !plan.install`; skipped when pnpm is `old`)
  5. `assertLockfileSubset`
  6. commit `chore: initial commit from create-ts-monorepo-starter <cli version> (template <tag>)`

  Any error removes the temporary folder and rethrows. `RunResult = { pnpm: PnpmStatus; installed: boolean; git: 'committed' | 'no-identity' | 'no-git' | 'inside-repo' | 'off'; packages: string[]; seconds: number }`.

The CLI uses `plainUi` when `-y` is set or stdin isn't a terminal.
- Produces: `helpText(): string` and `versionText(): string` = `create-ts-monorepo-starter <version> · template <tag>`

**Prompts (clackUi only):** folder (placeholder `my-ts-monorepo`) → "Use the recommended setup?" (Yes) → if No: scope (prefilled `defaultScope`), examples (multi-select, all checked, hints as in the Custom screen, at least one required), "Initialize git?" (Yes), "Install dependencies?" (Yes). A non-empty target asks `<folder> already has <n> files. Move them to <backup name> and continue?` (default No). Cancel at any prompt prints `Cancelled. Nothing was written.` and exits 130.
